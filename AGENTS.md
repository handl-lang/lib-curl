# lib-curl

codegen-generated libcurl FFI bindings — generic ports plus the
`c-linux-x86_64` adapters, emitted under `handl-packages/generated/`
(a gitignored build artifact). The committed spec
(`specs/curl.h` + `specs/curl.codegen.yaml`) re-declares the easy +
multi entry points because `hnl codegen c` only collects main-file
decls.

## Layout

| path | role |
| --- | --- |
| `specs/curl.h`, `specs/curl.codegen.yaml` | committed codegen inputs |
| `handl-packages/generated/` | gitignored build artifact — regenerated by the gate |
| `.handl/` | dev-time dep/path mappings |
| `pkg.hnl` | manifest — metadata only (no `src/` modules); `scripts:` block wires the `regen`/`gate` tasks |
| `scripts/hnl-gate.sh` | regenerates bindings, then typechecks/lints/tests `.hnl` sources |
| `workflows/gate.yaml` | CI — shared campaign; the regen leg needs the ext-codegen cdylib |

## Contract

- Never commit `handl-packages/generated/`; edit `specs/` and re-emit.
- Regenerate by hand:
  `hnl codegen c specs/curl.h --output handl-packages/generated/curl --config specs/curl.codegen.yaml`
  (needs libclang — `LIBCLANG_PATH` — and curl dev headers).
- `hnl run regen` is the cacheable codegen leg of the gate;
  `HNL_GATE_SKIP_REGEN=1` skips re-emitting inside `hnl-gate.sh`.

## Verification

```bash
HNL=../host-cli/target/debug/hnl scripts/hnl-gate.sh
```
